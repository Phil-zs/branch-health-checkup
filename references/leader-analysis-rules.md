# 负责人需关注能力分析规则

负责人分析只展开能力等级为`待提升`或`预警`的维度。`优秀`、`良好`和`达标`能力仅在汇总、雷达图和负责人明细附录中出现。

## 关键指标选择

对每个需关注能力，计算每项负责人指标相对满分的加权拖累：

```
指标影响度 = 指标权重 × (100 - 指标得分)
```

仅保留影响度大于零的前 1—2 项。得分相同按 `leader-rules.json` 中的指标顺序选择。影响度只用于内部选择关键指标，不在报告中展示，也不等同于已经确认的业务因果。

## 证据方式

1. 数值型指标有至少两个历史观察值时，展示近五年轨迹；若提供同类输入，且每个期间都有同类有效数据，则加入同类均值虚线。
2. A/B/C/D 等级型指标保留原始等级展示，按内置等级得分绘制轨迹。历史等级不得改写为负责人能力等级。
3. 当数字化应用力的两项证据恰为“二次业务线索执行率”和“二次业务线索转化率”时，展示两环节经营链路；这不是数量漏斗，不推断未提供的客户数或线索数。
4. 无法形成历史轨迹时，仅在“可能原因”中展示本期表现与限定性的归因判断；不展示指标得分、加权拖累、评分档位或其他计算过程。

本期或历史期间标记为截至期时，图表用于观察轨迹，不能将其与完整年度直接判断增减。

## 卡片内容

每张负责人能力卡依次显示：能力名称和等级、当前得分与五档能力阈值、可能原因、关键指标图形证据（如适用）、建议措施。趋势观察、归因判断和知识库原因共同构成“可能原因”，不创建单独的趋势解读栏目。可能原因和建议措施按能力维度 ID、能力等级、营业部类别、经营标准从独立知识库匹配；“可能原因”始终是待验证假设。
